# Техническое задание: кинотрекер для клуба кинолюбителей

Версия 1.5 · 24 октября 2026 года.

## 1. Назначение и границы

REST API на Python и FastAPI для одного закрытого киноклуба. Участники ищут фильмы во внешнем каталоге, добавляют их в клуб, оценивают по шести категориям, читают анонимные отзывы и сравнивают клубные и внешние рейтинги. Основные сценарии выполняются через Swagger `/docs` без отдельного интерфейса.

Все участники имеют одинаковые права: доступ к каталогу клуба и изменение собственной обратной связи. Регистрация — по приглашению организатора через CLI. Отдельная административная панель, несколько клубов, история изменений и персональные рекомендации в первую версию не входят; подбор реализуется поиском, фильтрами и сортировкой.

[README](README.md) содержит установку, таблицу настроек, команды запуска и проверки, ручной сценарий и диагностику. Этот документ задаёт правила приложения и контракт API.

## 2. Учётные записи и доступ

- Email проверяется сервером, очищается от пробелов по краям и приводится к нижнему регистру при создании приглашения, регистрации, входе и восстановлении. Нормализованный email уникален.
- Пароль: строка от 12 до 128 символов с сохранением пробелов и регистра. В БД хранится только Argon2-хеш; профиль содержит `id`, `email`, `created_at`.
- CLI создаёт криптографически случайное приглашение для конкретного email на 7 дней по умолчанию (`--days` допускает 1–365). Код показывается организатору один раз; в БД остаётся его хеш. Регистрация проверяет email, срок и одноразовость. Создание пользователя и погашение кода — одна транзакция, включая одновременные запросы.
- В JSON-запросах `invitation_code` и токен сброса `token` — строки длиной 20–256 символов.
- Вход по JSON email/паролю возвращает `access_token`, `token_type: bearer`, `expires_in` в секундах. Для неверного пароля и неизвестного email сообщение одинаковое. JWT действует 30 минут по умолчанию; срок настраивается.
- Защищённые запросы передают `Authorization: Bearer <token>`. Проверяются подпись с фиксированным HS256, срок, идентификатор существующего пользователя и `auth_version`.

Восстановление пароля:

1. Для корректного email в пределах IP-лимита возвращается `202` и `{"message":"Если аккаунт существует, инструкция отправлена на почту"}` независимо от наличия аккаунта. Поиск пользователя и SMTP выполняются после отправки ответа.
2. Для существующего участника создаётся случайный одноразовый токен на 30 минут. В БД сохраняется хеш; предыдущие токены пользователя аннулируются. Токен отправляется только письмом и вводится в Swagger вместе с новым паролем.
3. Подтверждение атомарно меняет хеш пароля, погашает все токены восстановления и увеличивает `auth_version`. Прежние JWT перестают работать; требуется новый вход.
4. Ошибка доставки записывается без email, токена и письма и не меняет нейтральный HTTP-ответ. Повторный запрос разрешён после ограничений. Локальная почта проверяется через тестовый SMTP, в автотестах отправщик подменяется.

| Ограничение | Лимит | Превышение |
|---|---|---|
| Вход, на IP | 10 попыток за 10 минут | `429` |
| Восстановление, на IP | 5 запросов за час | `429` |
| Письмо восстановления, на нормализованный email | 1 в минуту | Письмо подавляется, сохраняется `202` |

## 3. Оценки и отзывы

На пару «участник — фильм» приходится одна запись: `scores` и `review`. Оба поля передаются явно; каждое допускает `null`, но хотя бы одно должно содержать данные. Текст очищается от пробелов по краям; пустой считается отсутствующим, непустой имеет длину 1–5000 символов и выдаётся как обычный текст.

| Поле `scores` | Категория |
|---|---|
| `idea` | Идея |
| `plot` | Сюжет |
| `screenplay` | Сценарий |
| `acting` | Игра актёров |
| `sound` | Звук |
| `visuals` | Визуал |

Если `scores` не `null`, обязательны все шесть целых оценок 1–10. Дроби, булевы значения, пропущенные категории и выход за диапазон отклоняются. Клиент не передаёт `overall`, веса или `user_id`; лишние поля дают `422`. Автор определяется по JWT.

`PUT` создаёт или полностью заменяет собственную запись. `null` удаляет соответствующую часть; повторный одинаковый запрос не увеличивает число голосов. `DELETE` удаляет всю запись. Получить или изменить чужую запись через `/feedback/me` нельзя.

Общая оценка вычисляется сервером из исходных значений:

```text
overall участника = Σ(оценка категории × вес категории) / Σ(весов)
При равных весах: (idea + plot + screenplay + acting + sound + visuals) / 6
Клубный overall = среднее неокруглённых overall участников с оценками
```

- В первой версии все веса равны 1. Конфигурация содержит ровно шесть перечисленных категорий с конечными положительными весами, едиными для всего клуба. Использованные веса возвращаются в `rating_weights`.
- Исходные оценки сохраняются, производный `overall` не хранится отдельно. После изменения весов и перезапуска результаты пересчитываются при чтении без изменения числа голосов.
- `ratings_count` — число уникальных участников с `scores`; `averages` — средние по каждой категории. Каждый участник имеет одинаковый вес голоса. `reviews_count` — число непустых текстов, включая отзывы без оценок.
- Округление до двух знаков выполняется только при формировании ответа. Фильтрация и сортировка используют неокруглённые значения. Изменение или удаление записи отражается в статистике сразу.
- Без голосов `overall` и все значения `averages` равны `null`, `ratings_count = 0`. Без текстов `reviews_count = 0`. У записи без `scores` собственный `overall = null`.

Список отзывов содержит только `review_id` (случайный UUID), `text`, `created_at`; порядок — от старых к новым, при равной дате по `review_id`. Дата относится к созданию записи обратной связи, включая случай, когда текст добавлен позже оценок. Все отзывы доступны через страницы. Имя, email, `user_id` и ссылка на профиль не выдаются. Связь с автором сохраняется в БД для проверки прав; владелец БД технически может её увидеть.

## 4. Фильмы, поиск и подбор

Карточка клуба содержит `id`, уникальный `kinopoisk_id`, `title`, `original_name`, `year`, `description`, `genres`, `countries`, `film_length`, `poster_url`, `staff`, `external_ratings`, `external_updated_at`, `external_data_stale`, `metadata_incomplete`, `averages`, `overall`, оба счётчика и `rating_weights`.

`id` — внутренний идентификатор, `kinopoisk_id` — идентификатор источника; оба целые положительные. При импорте `kinopoisk_id` не принимает дроби и булевы значения. Фильмы сопоставляются по `kinopoisk_id`, а не по названию. Повторный импорт возвращает существующую карточку без дубля, в том числе при одновременных запросах.

Недостающие сведения источника — `null` или пустые списки; если нет названия, используется `Фильм {kinopoisk_id}`. Жанры и страны содержат `id` и `name` (неизвестный ID — `null`), съёмочная группа — `id`, `name`, `profession`, `role`, включая доступных актёров и режиссёров.

| Поиск | Параметры и значения |
|---|---|
| Внешний каталог | `query`, один `genre_id`, один `country_id`, `year_from`, `year_to`, `rating_from`, `rating_to`, `sort`, `page`; только тип `FILM` |
| Внешняя сортировка | `rating_desc` по умолчанию, `votes_desc`, `year_desc` |
| Локальный каталог | `query`, `genre_id`, `year_from`, `year_to`, `club_rating_from`, `min_votes`, `sort`, `page`, `page_size` |
| Локальная сортировка | `title_asc` по умолчанию, `year_desc`, `club_rating_desc`; равные значения — по внутреннему `id`, фильмы без рейтинга идут в конце рейтинговой сортировки |
| Диапазоны | Годы 1800–2200, рейтинги 0–10, нижняя граница не выше верхней; ID жанра/страны > 0, `min_votes` ≥ 0 (по умолчанию 0), `query` до 250 символов |
| Локальная пагинация | `page` ≥ 1, по умолчанию 1; `page_size` 1–100, по умолчанию 20. Ответ: `items`, `total`, `page`, `page_size`; после конца списка `items: []` |
| Внешняя пагинация | `page` 1–20, по умолчанию 1; по 20 результатов. Ответ: `items`, `total`, `total_pages`, `page`, `page_size` |

Фильтры необязательны. Локальный поиск по названию не учитывает регистр, включая кириллицу; `club_rating_from` применяется к клубному `overall`. Внешний ответ содержит краткие карточки: `kinopoisk_id`, названия, год, постер, жанры, страны и внешние рейтинги. Справочники возвращают `genres` и `countries`.

## 5. Внешние данные

Провайдер — [Kinopoisk API Unofficial](https://kinopoiskapiunofficial.tech/documentation/api/), сторонний неофициальный сервис. Ключ берётся из окружения и передаётся только сервером в `X-API-KEY`. Фактическая квота зависит от аккаунта провайдера; адаптер отделён от маршрутов и заменяется в тестах.

| Запрос провайдеру | Данные |
|---|---|
| `GET /api/v2.2/films` | Поиск и фильтры |
| `GET /api/v2.2/films/filters` | ID и названия жанров и стран |
| `GET /api/v2.2/films/{kinopoisk_id}` | Сведения о фильме и внешние рейтинги |
| `GET /api/v1/staff?filmId={kinopoisk_id}` | Съёмочная группа |

`external_ratings` содержит источники `kinopoisk` и `imdb`; для каждого — `rating`, `votes` и `data_provider: kinopoisk_unofficial`. Время снимка — `external_updated_at`. Неизвестные оценка и счётчик остаются `null`, а не нулём. Внешние общие оценки сравниваются с клубным `overall` и не заменяют категории клуба; числовые примеры в документации помечаются как условные.

- Карточка, съёмочная группа и рейтинги сохраняются в SQLite. Срок актуальности по умолчанию 24 часа, задаётся `EXTERNAL_CACHE_TTL_SECONDS`.
- `GET /api/v1/movies/{movie_id}` пытается обновить устаревший снимок. Локальный список не вызывает обновление. Успешная загрузка не меняет отзывы и оценки клуба; неполные данные не стирают ранее известные сведения.
- При сбое возвращаются сохранённые сведения с `external_data_stale: true` и временем последней успешной загрузки. Если первая карточка получена без съёмочной группы или части справочников, допускается `metadata_incomplete: true`; повторная попытка — при следующем обновлении после TTL.
- Поиск кэшируется в памяти на 10 минут по нормализованным параметрам, справочники — на 24 часа. Исходящие запросы ограничены двумя в секунду на процесс; таймаут одного вызова — 5 секунд, общий предел загрузки карточки — 10 секунд. Автоматических повторов нет.
- Без ключа приложение запускается; внешние операции дают `503 / external_service_not_configured`. Неверный ключ, квота, таймаут или сбой без сохранённых данных дают `503 / external_service_unavailable`; подтверждённое отсутствие фильма — `404 / movie_not_found`. Локальные чтение и обратная связь продолжают работать при сбое провайдера.

## 6. Контракт HTTP API

JSON; префикс прикладных маршрутов `/api/v1`. Обозначение «участник» означает обязательный Bearer-токен. `/docs` и `/openapi.json` открыты и описывают схемы, параметры, авторизацию и ошибки.

| Метод и маршрут | Доступ | Запрос и результат |
|---|---|---|
| `GET /health` | Открытый | `SELECT 1` к БД: `200 {"status":"ok","database":"ok"}`; при недоступности `503 {"status":"error","database":"unavailable"}`. Таблицы, миграции, кино API и SMTP не проверяются |
| `GET /version` | Открытый | `200 {"version":"<APP_VERSION>"}`, текущая версия по умолчанию `0.1.0` |
| `POST /api/v1/auth/register` | Открытый | `{email, password, invitation_code}` → `201` с профилем; `409` при занятом email, `422` при непригодном приглашении |
| `POST /api/v1/auth/login` | Открытый | `{email, password}` → `200` с JWT, типом и сроком; `401` при неверных учётных данных, `429` при лимите |
| `POST /api/v1/auth/forgot-password` | Открытый | `{email}` → нейтральный `202`; `429` при IP-лимите |
| `POST /api/v1/auth/reset-password` | Открытый | `{token, new_password}` → `204` без тела; `422` при непригодном токене |
| `GET /api/v1/users/me` | Участник | `200` с собственным профилем |
| `GET /api/v1/catalog/films` | Участник | Параметры внешнего поиска из §4 → `200` со страницей кратких карточек |
| `GET /api/v1/catalog/filters` | Участник | `200` со справочниками жанров и стран |
| `POST /api/v1/movies` | Участник | `{kinopoisk_id}` → `201` с карточкой; `200` при повторном импорте |
| `GET /api/v1/movies` | Участник | Параметры локального поиска из §4 → `200` со страницей карточек |
| `GET /api/v1/movies/{movie_id}` | Участник | `200` с карточкой, актуальными клубными средними и внешним снимком; `404`, если фильма нет |
| `GET /api/v1/movies/{movie_id}/feedback/me` | Участник | `200` с собственной записью; `404`, если фильма или записи нет |
| `PUT /api/v1/movies/{movie_id}/feedback/me` | Участник | `{scores, review}` по §3 → `200` с сохранённой записью; `404`, если фильма нет |
| `DELETE /api/v1/movies/{movie_id}/feedback/me` | Участник | `204` без тела; `404`, если фильма или записи нет |
| `GET /api/v1/movies/{movie_id}/reviews` | Участник | `page`, `page_size` по §4 → `200` со страницей анонимных отзывов; пустой список — `200`, неизвестный фильм — `404` |

Собственная запись в ответе содержит `scores`, `review`, `overall`, `created_at`, `updated_at`. Для всех маршрутов применяются проверка типов и ограничений; некорректный `movie_id`, тело или параметры дают `422`. Внешние ошибки из §5 применяются к поиску, справочникам и первому импорту; сохранённая карточка доступна при сбое обновления.

Все ответы содержат `X-Request-ID`. Ошибки, кроме указанного ответа `/health`, имеют объект `error` с `code`, `message`, `request_id` и необязательным `details` — списком `{field, type}` без отправленных значений.

| HTTP | `error.code` и причина |
|---|---|
| `401` | `unauthorized` — нет действующего access token; `invalid_credentials` — неверный вход. Заголовок `WWW-Authenticate: Bearer` |
| `404` | `movie_not_found`, `feedback_not_found` — отсутствует сущность; `http_error` — неизвестный маршрут |
| `405` | `http_error` — метод не поддерживается маршрутом |
| `409` | `email_already_registered` |
| `422` | `validation_error`, `invalid_invitation`, `invalid_reset_token` |
| `429` | `rate_limit_exceeded` |
| `503` | `external_service_not_configured`, `external_service_unavailable` |
| `500` | `internal_error`, без внутренних подробностей |

## 7. Хранение, запуск и журнал

Python 3.12, FastAPI, Uvicorn, Pydantic, SQLAlchemy, SQLite, Alembic, HTTPX, PyJWT, Argon2; pytest и Ruff для проверки. Маршруты, схемы, модели, расчёты, адаптер провайдера, почта и конфигурация разделены на модули.

| Сущность | Сохраняемые данные |
|---|---|
| `User` | `id`, уникальный email, `password_hash`, `auth_version`, `created_at` |
| `Invitation` | `id`, email, уникальный `token_hash`, `expires_at`, `used_at` |
| `PasswordResetToken` | `id`, `user_id`, уникальный `token_hash`, `expires_at`, `used_at` |
| `Movie` | Внутренний и внешний ID, метаданные, внешний снимок, время обновления, признак неполноты |
| `Feedback` | UUID, `user_id`, `movie_id`, шесть исходных оценок или весь блок `null`, текст, время создания и изменения |

БД обеспечивает внешние ключи с включённым SQLite `foreign_keys`, уникальность email, `kinopoisk_id` и пары `(user_id, movie_id)`, полноту блока оценок и диапазоны. Даты — UTC, выдача ISO 8601. Жанры, страны, съёмочная группа и внешние рейтинги допускают JSON-поля; фильтры проверяются на используемой SQLite. Схема создаётся миграциями Alembic, данные сохраняются после перезапуска.

`app_final.py` экспортирует фабрику `app.main.create_app`. Импорт не создаёт приложение и не требует рабочего секрета. Запуск — через `app_final:create_app --factory` без `--reload`, одним процессом. Кэш, лимиты и фоновая отправка писем находятся в памяти процесса, без постоянной очереди доставки; они не разделяются между workers.

Настройки читаются из окружения и локального `.env`; перечень и значения по умолчанию — в README и `.env.example`. `JWT_SECRET` обязателен, не имеет рабочего значения по умолчанию, длина от 32 символов; ошибки настроек не раскрывают секретов. `LOG_LEVEL` меняет уровень журнала после перезапуска. Работа с реальными аккаунтами при публичном размещении — через HTTPS.

В журнал сервера выводятся запуск, завершение, версия; для запросов — метод, путь без query string, статус, длительность и `request_id`; для изменений фильмов и обратной связи — событие и `movie_id`. Фиксируются ошибки БД, квоты и таймауты провайдера, результат обновления карточки и сбои почты. Исключения дают диагностический тип и позиции стека без приватных значений.

Запрещены в ответах ошибок и журнале пароли, токены, приглашения, заголовки авторизации, API-ключи, SMTP-пароли, тела писем и запросов авторизации; в журнале также отсутствуют тексты отзывов и связь автора с отзывом. Отладочный вывод чувствительных заголовков HTTP-клиента отключён.

## 8. Автоматические проверки и CI

`python -m pytest -v` собирает корневой `test_app.py` и `tests/`, общие фикстуры — в `conftest.py`. В корневом файле минимум три содержательные проверки: `/health`, полезный маршрут и маршрут с параметром, включая ошибку. Проверки БД используют изолированные временные SQLite; кино API и SMTP подменяются. Для сценариев не нужны настоящий `.env`, ключи, интернет и отправка писем.

Обязательное покрытие:

- Запуск, `/health`, `/version`, недоступная БД, безопасные ошибки и журнал.
- Приглашения: успех, повтор, чужой email, истечение и параллельное погашение; вход с верным/неверным паролем, отсутствие, истечение и подделка JWT.
- Восстановление: одинаковый ответ для существующего/отсутствующего email, подменённая почта, лимиты, истёкший/повторный токен, смена пароля и отзыв прежних JWT.
- Фильмы: импорт, сохранение после перезапуска, отсутствие дублей, неизвестный ID, оба поиска, фильтры, сортировки и пагинация.
- Оценки: все шесть полей; отклонение 0, 11, дробей, булевых значений, неполного блока, `overall` и весов; равные и неравные тестовые веса, отсутствие промежуточного округления, пересчёт при смене весов, средние и счётчики, повтор/изменение/удаление, `null` без голосов.
- Отзывы: текст без оценок, оценки без текста, запрет пустой записи и чужого редактирования, отсутствие автора в ответе, получение всех страниц.
- Провайдер: кэш, таймаут, квота, неверный ключ, отсутствующий рейтинг, неполный ответ, сохранённые данные при сбое и локальная работа без ключа; ограничения уникальности и внешних ключей БД.

Workflow `.github/workflows/ci.yml`: название `CI`, задание `checks`, Ubuntu и Python 3.12, права `contents: read`. Запускается на `pull_request` в `main` при открытии, повторном открытии и новых коммитах, затем на `push` в `main`. Обычный push рабочей ветки без PR запуск не создаёт.

Отдельные обязательные шаги: checkout, установка зависимостей разработки по зафиксированным версиям, `python -m ruff check .`, миграция новой временной SQLite через `python -m alembic upgrade head`, `python -m pytest -v`. Используются `APP_ENV=test` и отдельный тестовый `JWT_SECRET`. Ошибки шагов и отсутствие собранных тестов не подавляются.

После успеха публикуется артефакт `cinema-club-tracker-source` на 7 дней. Он содержит только явно перечисленные исходники, миграции, тесты, зависимости, конфигурацию и документацию с `.env.example`; настоящие `.env`, базы, письма, логи, окружение и кэши исключены. Получение архива и чтение журналов Actions описываются в README.

## 9. Поставка и работа с репозиторием

Проект размещается в публичном GitHub-репозитории. Восемь обязательных файлов:

| Файл | Назначение |
|---|---|
| `app_final.py` | Точка входа с фабрикой |
| `requirements.txt` | Зависимости запуска с ограничениями `requirements.lock` |
| `requirements-dev.txt` | Зависимости приложения, тестов и линтера |
| `test_app.py` | Минимум три проверки API |
| `README.md` | Установка, запуск, проверка, диагностика |
| `.gitignore` | Исключение секретов и локальных данных |
| `.env.example` | Пример настроек без рабочих секретов |
| `.github/workflows/ci.yml` | Проверки и артефакт |

В репозитории также находятся `app/`, `migrations/`, `tests/`, `conftest.py`, `requirements.lock`, `pyproject.toml`, `alembic.ini`, это ТЗ, `AGENTS.md` и шаблон PR. Версии зависимостей фиксируются в lock-файле; `requirements-dev.txt` включает зависимости запуска. Восемь файлов не заменяют остальные модули проекта.

README должен позволять воспроизвести установку и запуск без `--reload`, применение миграций, создание первого приглашения, цепочку от входа до оценки и статистики, восстановление пароля, проверку `/health` и `/version`, тесты и Ruff. Он содержит настройки окружения, инструкции для провайдера и SMTP, диагностику по логам и `request_id`, ссылку на CI, получение артефакта и ограничения одного процесса.

Настоящий `.env`, его локальные варианты, базы с пользовательскими данными, письма, логи, виртуальное окружение и кэши исключаются через `.gitignore`. Секреты и данные участников не допускаются в примерах, текущих файлах, истории Git и артефактах.

Правила изменений — в [AGENTS.md](https://github.com/mkang131/cinema-club-tracker/blob/main/AGENTS.md): новая задача начинается от обновлённой `main` в ветке `feature/`, `fix/`, `docs/` или `chore/`; одна задача — одна ветка и один PR. Описание PR содержит проблему, результат и проверки, при изменении требований — ссылку на ТЗ. Учебный ориентир — не менее шести осмысленных коммитов по этапам проекта без искусственного дробления.

`main` защищена, включая изменения администратора: только PR, актуальная относительно `main` ветка и успешный обязательный `checks` на её текущей версии. Второй рецензент не обязателен. После слияния проверяется итоговая `main`.

Приёмка: инструкции README воспроизводятся после клонирования; все требования разделов 2–8 подтверждены тестами или указанным ручным сценарием; на актуальном коде есть успешный `checks` и доступный артефакт исходников. Заведомая ошибка линтера или теста должна приводить к неуспешному CI.
