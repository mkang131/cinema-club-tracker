# Правила работы с проектом

- Перед новой задачей обновить локальную `main` из GitHub и создать от неё отдельную ветку с понятным именем: `feature/<slug>` для функции, `fix/<slug>` для исправления, `docs/<slug>` для документации, `chore/<slug>` для обслуживания проекта.
- Одна задача — одна ветка и один pull request (PR). Не объединять несвязанные изменения.
- Не коммитить напрямую в `main`. Изменения попадают в `main` через PR.
- В описании PR объяснить проблему, что изменилось и как проверено. Если менялось ТЗ, дать ссылку на обновлённый документ.
- При изменении кода выполнять Ruff и pytest. Проверять результат CI в GitHub Actions и исправлять ошибки до завершения задачи.
- CI запускается для открытых PR в `main` при создании и новых коммитах и повторно после слияния в `main`. Сливать PR только после успешной обязательной проверки `checks` на актуальной версии ветки.
- Не публиковать секреты, настоящий `.env`, токены, пароли и пользовательские данные. Для примеров использовать только безопасные значения.
