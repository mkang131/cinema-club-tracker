# Cinema Club Tracker

[![CI](https://github.com/mkang131/cinema-club-tracker/actions/workflows/ci.yml/badge.svg)](https://github.com/mkang131/cinema-club-tracker/actions/workflows/ci.yml)

Учебный бэкенд на FastAPI для закрытого клуба кинолюбителей. Участники находят фильмы, добавляют их в каталог клуба, оставляют оценки и отзывы и сравнивают клубную оценку с рейтингами Кинопоиска и IMDb.

Регистрация работает по одноразовым приглашениям. Каталог, оценки и отзывы доступны после входа. В списке отзывов другие участники не видят автора; в базе автор сохраняется для проверки прав и изменения собственной записи. Это анонимность внутри клуба, а не перед владельцем базы данных.

Стек: Python 3.12, FastAPI, SQLAlchemy, SQLite, Alembic, HTTPX, Pydantic, JWT и Argon2. Тесты — pytest, линтер — Ruff. Подробные требования: [ТЗ](TECHNICAL_SPECIFICATION.md).

## 1. Установка

Нужны Python 3.12 и Git. Все команды выполняются из папки проекта.

```powershell
git clone https://github.com/mkang131/cinema-club-tracker.git
cd cinema-club-tracker
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.lock
Copy-Item .env.example .env
```

В Linux/macOS создание окружения и копирование настроек выглядят так:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
cp .env.example .env
```

Для первого запуска сгенерируй собственный `JWT_SECRET`. Эта команда записывает случайный секрет непосредственно в локальный `.env`, не выводя его в терминал:

```powershell
python -c "from pathlib import Path; import secrets; p=Path('.env'); p.write_text(p.read_text(encoding='utf-8').replace('JWT_SECRET=', 'JWT_SECRET=' + secrets.token_hex(32), 1), encoding='utf-8')"
```

Команда одинаковая для PowerShell и Linux. Её нужно выполнить один раз после копирования примера. Не перезаписывай существующий `.env` при повторном запуске. Переменные окружения процесса имеют приоритет над `.env`.

## 2. Настройки

В репозитории есть только безопасный [.env.example](.env.example). Настоящий `.env`, базы данных, письма, логи и виртуальное окружение исключены через `.gitignore`.

| Переменная | Значение и назначение |
|---|---|
| `APP_ENV` | `development`, `test` или `production` |
| `APP_VERSION` | Версия `/version`, по умолчанию `0.1.0` |
| `DATABASE_URL` | SQLite, по умолчанию `sqlite:///./data/cinema.db` |
| `LOG_LEVEL` | `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL`; по умолчанию `INFO` |
| `JWT_SECRET` | Обязательный приватный случайный секрет, минимум 32 символа |
| `ACCESS_TOKEN_TTL_MINUTES` | Срок access token, по умолчанию 30 минут |
| `RATING_WEIGHTS` | JSON с шестью положительными весами, по умолчанию все равны 1 |
| `KINOPOISK_API_KEY` | Необязательный ключ внешнего каталога |
| `EXTERNAL_CACHE_TTL_SECONDS` | Срок актуальности сохранённой карточки, по умолчанию 86400 секунд |
| `SMTP_HOST`, `SMTP_PORT` | SMTP-сервер; локальный пример — `localhost:1025` |
| `SMTP_USER`, `SMTP_PASSWORD` | SMTP-учётные данные; для локального Mailpit пустые |
| `SMTP_FROM` | Адрес отправителя |
| `SMTP_TLS` | `true` включает STARTTLS; для локального Mailpit — `false` |

После изменения настроек перезапусти приложение. Ключ Кинопоиска и SMTP не нужны для запуска сервиса, регистрации, входа и работы с уже сохранённым каталогом. Без кино API нельзя искать и импортировать новые фильмы.

## 3. Создание базы и запуск

Примени миграции; папка `data` создаётся автоматически:

```powershell
python -m alembic upgrade head
python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000 --no-access-log
```

По умолчанию запускается один рабочий процесс. SQLite сохраняет фильмы, участников и обратную связь после перезапуска. Схему создают миграции, запуск сервера не заменяет их применение.

- [Swagger UI](http://127.0.0.1:8000/docs) — интерактивная документация и отправка запросов.
- [Health](http://127.0.0.1:8000/health) — при доступной БД возвращает `{"status":"ok","database":"ok"}`.
- [Version](http://127.0.0.1:8000/version) — возвращает текущую версию.

Проверка из PowerShell:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
Invoke-RestMethod http://127.0.0.1:8000/version
```

В Linux можно использовать `curl http://127.0.0.1:8000/health`. Сервер останавливается через `Ctrl+C`.

## 4. Первый участник и полный сценарий в Swagger

Оставь сервер работающим, открой второй терминал в папке проекта и активируй окружение. Организатор создаёт приглашение для конкретного email:

```powershell
python -m app.cli create-invite --email member@example.org
```

Код выводится один раз, действует 7 дней и используется только для указанного адреса. Передай его участнику приватно. В базе хранится хеш кода.

В Swagger для каждого запроса нажми **Try it out**, заполни данные и нажми **Execute**. Значения в угловых скобках ниже нужно заменить собственными.

1. **Зарегистрируйся:** `POST /api/v1/auth/register`:

   ```json
   {
     "email": "member@example.org",
     "password": "<собственный пароль от 12 до 128 символов>",
     "invitation_code": "<код из CLI>"
   }
   ```

   Успешный ответ — `201`. Email приводится к нижнему регистру и очищается от пробелов по краям; пароль сохраняет пробелы и регистр.

2. **Войди:** `POST /api/v1/auth/login`. Передай JSON с теми же `email` и `password`. Из ответа скопируй `access_token`. Нажми **Authorize** вверху Swagger и вставь только токен: Swagger сам добавит `Bearer`. Проверить вход можно через `GET /api/v1/users/me`.

3. **Найди фильм:** `GET /api/v1/catalog/films?query=Матрица`. Запрос требует настроенного ключа провайдера. Доступны `genre_id`, `country_id`, `year_from`, `year_to`, `rating_from`, `rating_to`, `sort` и `page`. Идентификаторы жанров и стран возвращает `GET /api/v1/catalog/filters`. Сортировки: `rating_desc`, `votes_desc`, `year_desc`.

4. **Добавь фильм в клуб:** `POST /api/v1/movies`, например `{"kinopoisk_id":301}`. Используй внешний идентификатор из поиска. При первом добавлении возвращается `201`, при повторном — существующая карточка и `200`. Запомни внутренний `id` из ответа: последующие клубные маршруты используют именно его.

5. **Оставь оценки и отзыв:** `PUT /api/v1/movies/{movie_id}/feedback/me`:

   ```json
   {
     "scores": {
       "idea": 9,
       "plot": 8,
       "screenplay": 9,
       "acting": 8,
       "sound": 10,
       "visuals": 9
     },
     "review": "Понравились атмосфера и музыка."
   }
   ```

6. **Посмотри результат:** `GET /api/v1/movies/{movie_id}` возвращает описание, съёмочную группу, внешние рейтинги, средние клуба, `ratings_count` и `reviews_count`. `GET /api/v1/movies/{movie_id}/reviews` возвращает отзывы без полей автора. Для проверки общего среднего создай второго участника по новому приглашению и выставь другие оценки.

Для просмотра своего отзыва используй `GET /api/v1/movies/{movie_id}/feedback/me`, для удаления всей собственной записи — `DELETE` по тому же пути (`204`). Повторный `PUT` полностью заменяет свою запись и не добавляет голос. Оба поля `scores` и `review` обязательны в запросе: передай `null`, чтобы убрать соответствующую часть. Хотя бы одна часть должна остаться заполненной.

Локальный каталог `GET /api/v1/movies` поддерживает поиск `query`, фильтры `genre_id`, `year_from`, `year_to`, `club_rating_from`, `min_votes` и сортировки `title_asc`, `year_desc`, `club_rating_desc`. Для локального каталога и отзывов есть `page` и `page_size` (по умолчанию 1 и 20, максимум 100 записей на страницу). Отзывы можно получить полностью, последовательно прочитав страницы.

## 5. Как считаются оценки

Каждый участник отдельно оценивает **идею, сюжет, сценарий, игру актёров, звук и визуал**: `idea`, `plot`, `screenplay`, `acting`, `sound`, `visuals`. Все шесть полей обязательны, значения — целые числа 1–10. Общая оценка вычисляется сервером; передавать `overall` или веса в запросе нельзя.

```text
overall = Σ(оценка × вес) / Σ(вес)
```

В первой версии все веса равны 1: сумма шести оценок делится на 6. Клубная общая оценка — среднее неокруглённых общих оценок участников; каждый участник имеет один голос. Средние округляются до двух знаков только в ответах. Если голосов нет, средние — `null`, счётчик — 0.

В `RATING_WEIGHTS` должны быть ровно шесть перечисленных полей с конечными положительными числами. Настройка едина для всего клуба. Если изменить веса и перезапустить сервис, производные оценки пересчитаются из сохранённых исходных значений без изменения числа голосов. Использованные веса видны в `rating_weights` карточки.

Можно оставить только текст (`scores: null`) или только оценки (`review: null`). Поэтому число оценивших `ratings_count` и число текстовых отзывов `reviews_count` могут отличаться.

## 6. Внешний каталог и рейтинги

Источник — [Kinopoisk API Unofficial](https://kinopoiskapiunofficial.tech/), неофициальный сторонний сервис. Зарегистрируйся на его сайте, получи ключ в личном кабинете и запиши его только в `KINOPOISK_API_KEY` своего `.env`. Доступные квоты зависят от условий провайдера. Контракт интеграции описан в его [Swagger/OpenAPI](https://kinopoiskapiunofficial.tech/documentation/api/).

Адаптер использует поиск `/api/v2.2/films`, справочники `/api/v2.2/films/filters`, карточку `/api/v2.2/films/{id}` и съёмочную группу `/api/v1/staff`. Поиск ограничен фильмами типа `FILM` и 20 страницами по 20 результатов. Исходящие запросы ограничены двумя в секунду на процесс; таймаут одного вызова — 5 секунд, общий лимит загрузки карточки — 10 секунд. Автоматических повторов нет.

Поиск кэшируется в памяти на 10 минут, справочники — на 24 часа. Карточки и внешние рейтинги сохраняются в SQLite на срок `EXTERNAL_CACHE_TTL_SECONDS`; при чтении устаревшей карточки сервис пытается её обновить. При сбое сохраняются прежние сведения и возвращается `external_data_stale: true`. При частичной загрузке доступна карточка с `metadata_incomplete: true`; недостающие сведения запрашиваются при последующем обновлении.

Внешние рейтинги отделены от оценок клуба. Для Кинопоиска и IMDb возвращаются значение, счётчик голосов при наличии и поставщик `kinopoisk_unofficial`; дата снимка — `external_updated_at`. Отсутствующие значения остаются `null`.

Без API-ключа внешние операции возвращают `503 / external_service_not_configured`. Неверный ключ, квота, таймаут или сбой источника дают `503 / external_service_unavailable`; подтверждённое отсутствие фильма — `404`. Чтение сохранённого каталога и клубная обратная связь продолжают работать. Автотесты проверяют контракт подменёнными ответами; проверка живого API требует собственного действующего ключа.

## 7. Восстановление пароля и локальная почта

Для локальной проверки удобно использовать [Mailpit](https://mailpit.axllent.org/docs/install/docker/). Если установлен Docker:

```powershell
docker run -d --name cinema-mailpit -p 127.0.0.1:1025:1025 -p 127.0.0.1:8025:8025 axllent/mailpit
```

В `.env.example` уже указаны `SMTP_HOST=localhost`, `SMTP_PORT=1025`, пустые SMTP-учётные данные и `SMTP_TLS=false`. Просмотр писем — [Mailpit](http://127.0.0.1:8025). Это локальная тестовая доставка; письма не отправляются в настоящий почтовый ящик.

В Swagger вызови `POST /api/v1/auth/forgot-password` с `{"email":"member@example.org"}`. Корректный по формату адрес получает одинаковый ответ `202`: «Если аккаунт существует, инструкция отправлена на почту». Открой письмо в Mailpit и перенеси код в `POST /api/v1/auth/reset-password`:

```json
{
  "token": "<одноразовый код из письма>",
  "new_password": "<новый собственный пароль от 12 до 128 символов>"
}
```

Код действует 30 минут. Новое письмо аннулирует предыдущий код. Успешный сброс (`204`) отменяет все прежние JWT пользователя: нужно войти заново. Токен не возвращается в HTTP-ответе и не выводится в логи. Ошибка SMTP не меняет нейтральный ответ; запрос можно повторить позднее.

Лимиты: вход — 10 попыток за 10 минут на IP; восстановление — 5 запросов в час на IP и не более одного письма в минуту на email. При превышении IP-лимита возвращается `429`. Для настоящего SMTP задай параметры своего провайдера и `SMTP_TLS=true` для STARTTLS; для публичного развёртывания используй HTTPS.

## 8. Тесты и CI

После установки зависимостей:

```powershell
python -m ruff check .
python -m pytest -q
```

Тесты используют отдельные временные SQLite, подменяют SMTP и кино API, а HTTPX-адаптер проверяют через MockTransport. Настоящий `.env`, API-ключи, интернет и отправка писем для тестовых сценариев не нужны. Проверяются авторизация, приглашения и восстановление, фильмы и фильтры, шесть оценок и агрегаты, анонимные отзывы, кэш и сбои провайдера, ограничения БД и приватность ошибок.

Проверить миграции на новой базе отдельно от рабочей можно из нового PowerShell-терминала с активированным окружением:

```powershell
$env:APP_ENV = 'test'
$env:JWT_SECRET = python -c "import secrets; print(secrets.token_hex(32))"
$env:DATABASE_URL = 'sqlite:///./data/migration-check.db'
python -m alembic upgrade head
python -m alembic current
```

Выбери новое имя файла, если `migration-check.db` уже существует. После проверки закрой этот терминал, чтобы тестовые переменные не влияли на рабочий запуск. В Linux аналог: `APP_ENV=test JWT_SECRET="$(python -c 'import secrets; print(secrets.token_hex(32))')" DATABASE_URL=sqlite:///./data/migration-check.db python -m alembic upgrade head`.

Workflow [CI](https://github.com/mkang131/cinema-club-tracker/actions/workflows/ci.yml) находится в [.github/workflows/ci.yml](.github/workflows/ci.yml). Он проверяет PR в `main` при открытии, повторном открытии и новых коммитах, затем повторно запускается после слияния при `push` в `main`. Отдельный push в рабочую ветку без PR CI не запускает. Проверки: Ubuntu, Python 3.12, установка `requirements.lock`, Ruff, миграции новой SQLite и pytest. Ошибка любого шага делает проверку неуспешной. Рабочие секреты CI не требуются, права workflow — `contents: read`.

Для диагностики открой **Actions → CI → нужный запуск → checks → неуспешный шаг**. Его журнал содержит команду и причину ошибки. Те же команды выше воспроизводят проверки локально.

## 9. Диагностика и ограничения

Логи идут в терминал сервера: запуск и завершение, версия, метод и путь без query string, статус, время обработки, `request_id`, изменения фильмов и ошибки внешних сервисов. Заголовок `X-Request-ID` и поле `error.request_id` помогают найти запрос. `LOG_LEVEL=WARNING` сокращает вывод; после изменения нужен перезапуск. Пароли, токены, API-ключи, тела писем и тексты отзывов в логи не записываются.

| Проблема | Что проверить |
|---|---|
| Сервер не запускается: ошибка настроек | Заполнен ли `JWT_SECRET` длиной от 32 символов; корректен ли JSON `RATING_WEIGHTS`; запускается ли команда из папки проекта |
| PowerShell блокирует `Activate.ps1` | Используй `.\.venv\Scripts\python.exe` вместо `python` в командах без активации |
| Порт 8000 занят | Останови предыдущий сервер или выбери `--port 8001` и открой соответствующий адрес |
| `no such table` | Выполни `python -m alembic upgrade head` с тем же `DATABASE_URL`, что у сервера; `/health` проверяет соединение, а не наличие таблиц |
| `/health` возвращает `503` | Проверь путь и права доступа к SQLite, `DATABASE_URL`, доступность диска и серверный лог |
| Защищённый маршрут возвращает `401` | Войди снова и обнови токен в Authorize; токен мог истечь или быть отменён сбросом пароля |
| Регистрация возвращает `422` | Проверь email приглашения, срок, одноразовость кода и длину пароля |
| Внешний каталог возвращает `503` | Проверь наличие ключа, квоту и доступность провайдера; локальные данные остаются доступны |
| Не приходит письмо | Проверь Mailpit/SMTP, адрес участника, лог `mail_delivery_failed` и лимиты; `202` не подтверждает наличие аккаунта или доставку |
| Запрос получает `422` | Посмотри `error.details` и схему Swagger: поля оценок целые, все шесть обязательны; `overall` передавать нельзя |
| Проверка CI красная | Открой журнал упавшего шага `checks`, затем повтори его команду локально |

Первая версия предназначена для небольшого клуба и одного процесса Uvicorn. Кэш и лимиты находятся в памяти и сбрасываются при перезапуске; несколько workers не разделяют их состояние. Локальные фильтры и сортировки выполняются в Python, что подходит для небольшого каталога. Нет фронтенда, нескольких клубов и персональных рекомендаций. Восстановление отправляется фоновой задачей процесса без постоянной очереди доставки. Для размещения с реальными участниками нужны приватные настройки, HTTPS и резервное копирование SQLite; файлы базы и `.env` не публикуются в Git.

## 10. Работа над новой функцией

Каждая задача выполняется в отдельной ветке от обновлённой `main`:

```powershell
git switch main
git pull --ff-only
git switch -c feature/movie-watchlist
```

Название описывает задачу: `feature/movie-watchlist`, `fix/rating-count`, `docs/setup-guide` или `chore/update-dependencies`. После изменений проверь код локально, сделай коммит и отправь рабочую ветку в GitHub. Создай Pull Request в `main` с описанием проблемы, изменений и результатов проверки; GitHub предложит [шаблон PR](.github/pull_request_template.md).

Перед слиянием дождись успешного `checks`. Если `main` изменилась, обнови рабочую ветку и дождись новой проверки. Ветка `main` защищена: изменения проходят через PR с успешным CI, включая изменения владельца репозитория. Отдельный второй рецензент для слияния не требуется. После слияния CI проверяет итоговую `main` ещё раз.

Полные правила для работы с репозиторием: [AGENTS.md](AGENTS.md). Одна задача — одна ветка и один PR.
